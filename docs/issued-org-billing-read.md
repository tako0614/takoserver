# Issued organization billing read supplier

This Node operator-side adapter reads an already issued Takoserver organization API key for one exact organization. It is a source for internal `apiKeyFor(organizationId)` consumers and a bounded local reader of the Server's billing facts. It does not issue or refresh keys, start owner sessions, create a Worker binding, or install a key in Hosted. A deployed Hosted dashboard still needs an independently selected runtime credential transport.

The caller selects an exact HTTPS Server origin, environment, organization ID, lowercase key name, source commit, mint receipt path, and existing secret directory. The receipt must be an original `takoserver.org-api-key-mint@v1` result from `takoserver-org-api-key`, with `action: mint`, the selected environment, commit, organization, name, a key ID, exactly `wallet:read`, canonical timestamps, and the deterministic secret path `<secretDirectory>/<organizationId>.<keyName>.secret`. Its successful product/OpenAPI probe URLs must match the selected origin. The issuer's one-time file contains the raw key with no newline. The files must be owned mode 0600, and their immediate parent directories owned mode 0700; higher read-only ancestors are allowed. Symlink, hard link, permission, file replacement, malformed, missing, expired, and origin mismatch cases refuse with one generic error. A historical key listing cannot prove that a secret file belongs to a key ID; custody derives from the original mint receipt and protected file.

`apiKeyFor` exposes the raw key only to the internal credential port for the selected organization. `readFacts` uses the same key for exactly `GET /v1/organizations/{organizationId}/wallet/usage-summary` and `GET /v1/organizations/{organizationId}/payments/subscription` at the selected Server origin. It returns `{ usageSummary, subscription }`, where each value is the complete JSON body from its respective Server endpoint, including fields such as `planTable` in the subscription body. It sends Bearer authorization and JSON accept headers, follows no redirects, uses a bounded deadline and response size, and makes no retry or fallback call. It checks returned organization-bearing data; a null subscription has no organization field, so the exact route's live authorization supplies that boundary. The Server's live route authentication and `wallet:read` check remain the permission authority on each GET: a revoked key receives a refusal even while its protected file and old receipt still exist. The receipt is custody evidence, not a current grant.

This key is a service read credential. It conveys no human payer intent or consent to mutate money. Keep the receipt and raw key in operator-private storage outside Git; do not log or print either key bytes or response bodies. Rotation means using the issuer to mint a new key, selecting its new receipt/file, and revoking the old key through the existing owner-authorized route.
