# Original RP Principal input

The RP exports `SharedAuthVerifiedPrincipalInput` (opaque), `SharedAuthVerifiedPrincipalData`, and `readSharedAuthVerifiedPrincipalInput(originalRpReceiver, capture)`. A capture is issued only inside `createSharedAuthSession`, passed as the second argument of its already-captured `principals.resolve(DATA, original)` method, and read through a literal import of this owning module. One-argument compatibility implementations retain ordinary behavior. Root must bind the actual RP receiver before serving the graph; this module does not install a Root issuer or classified branch.

A fresh-callback capture follows actual exchange/nonce validation, active-grant check, canonical-account equality, directory/bootstrap personal ownership and current personal Workspace owner selection. It precedes Principal resolution and session creation. It attests that RP observation, not committed session/SQL acceptance, distinct human, qualified Clock, registered physical103 target/current admission or genuine Root Principal authority. No token, assertion, nonce, cookie, sealed grant or secret is exposed.

The static reader returns frozen detached identity (`issuer/clientId/subject/sessionId/authTime/accountId`), selected Workspace, and phase. Unknown/cloned/inherited/other-factory captures or copied receivers return null without inspecting caller properties. For authentic handles it compares own-data descriptors/prototypes of the actual RP options/config/principal and optional Organization ports/key bytes, returned RP method receiver and selected store. Replaced accessors are compared without running getters. It proves identities at read time, not unobserved historical continuity or external-port honesty/qualification. Legacy ordinary resolution is not promoted by this type.

`fresh-callback` has no session postimage/version/durable acceptance field. `existing-session` is retained-binding lookup only: Root must read the already retained exact original binding and refuse absent/conflicting/legacy-unknown enrollment, never autoenroll or fall back to fresh creation. `sessionObservation` holds original session digest/creation/Workspace/Principal, the version read before refresh and the version at Principal resolution. These observations are neither registration/enrollment versions nor the later final-touch version. Selected Workspace may be an Org while original session Workspace stays personal. Registration/ref/digest/enrolled version remain Root durable inputs, never inferred from a grant.

Ordinary session SQL/class pair, callback ordering, cookie/orphan queue/revocation and unknown-ACK no retry remain unchanged. A pre-create capture may remain readable after an unknown create acknowledgement; this is not permission to resend, mint a key, autoenroll, recover NEW or issue a cookie. Root named issuer/Principal+anchor+binding batch/composition, human/103/Clock/admission and eventual session/class integration remain separate owning work.

The original v3 focused validation used an immutable private Root409 source mirror, a signed synthetic HTTP issuer and an explicit local memory RP store. The historical statement that nothing was publicly adopted/pushed described that private unit. Its exact original-input source was subsequently published as component `3ca1375d`, with separate public-parent scoped type and whole-session checks. This fresh-write extension needs its own source/check/adoption evidence; it inherits neither the historical private graph qualification nor a Root mount. All such local tests qualify RP mechanics, not native D1/common-primary, Root/Financial authority or a mounted production path.

Descriptor snapshot collection can itself be unavailable (for example an ordinary options/store Proxy rejects enumeration). Collection failures, including options child-descriptor collection, make the new reader return null; they do not add an enumeration exception to the ordinary compatibility callback. This does not accept a forged input or downgrade an unavailable selected qualified reader into ordinary authority.

The returned RP receiver alone allows the existing Root `Object.freeze(createSharedAuthSession(...))` wrapper to harden writable/configurable true to false. This exception requires actual full Object.isFrozen, unchanged prototype/own keys/enumerability and exact data values/method identities. Accessors, replaced values and partial attribute changes remain rejected. No freeze exception applies to options/config/store/other ports, and ordinary receivers are not forcibly frozen by this API.

The original reader supports a selected session store only when every required SharedAuthSessionStore method is an own data callable. Class/prototype/inherited method implementations stay supported by the ordinary RP path but yield null original input; no prototype graph is traversed or method getter invoked. Own literal store methods are sealed by their original descriptors and values. This avoids a positive input after dynamically re-read inherited createSession/readSession methods change on an unchanged prototype object. The captured Principal resolver itself retains its original callable through Reflect.apply; it is not classified as the same dynamic-store issue.


## Original fresh session write DATA

`readSharedAuthFreshSessionWrite(originalRpReceiver, record)` reads only the exact callback-generated `OidcSessionRecord` object while its one original `store.createSession(record)` invocation is active. It returns frozen `SharedAuthFreshSessionWriteData` with the already-issued `original` Principal input and a detached readonly `session` snapshot. The callback constructs the same eleven primitive fields in the original order, with the same encrypted-grant seal await and selected stamp/version0/statusactive. No extra Clock or crypto await, callback, SQL, schema, external wire, record freeze, or additional create write is introduced. The createSession callable is selected exactly once before the grant seal await, at the original JavaScript callee-evaluation point, and invoked with the original store receiver. An await-time method substitution makes the owning DATA reader unavailable while ordinary dispatch still invokes that selected original callable. The actual record passed to the ordinary store stays mutable as before; the reader detects subsequent changes through descriptors and values.

Unknown/null/clone/Proxy/inherited-record objects or foreign receivers are rejected by private identity lookup without caller getter/property inspection. An authentic record still needs the existing same-factory/config/key/store/callable/receiver seals, a fresh-callback original, and unchanged record keys/prototype/data descriptors and all eleven field values. Only the existing full receiver-freeze exception applies. Ordinary descriptor-unavailable or inherited stores continue ordinary behavior and receive no qualified fresh-write DATA. Retained-session observation never registers a fresh write, never reopens its old record and never enrolls missing authority.

The association is opened immediately before the existing create call and closed in its finally on true, false, throw or unknown acknowledgement, before the outer callback failure handling. A later read of that record returns null. The returned snapshot is only original call DATA, not a commit receipt, durable phase, Principal/human enrollment, NEW permission or permission to retry. Its payload is the original encrypted grant already delivered to the owning store; this reader introduces no raw grant, token, assertion, authorization code, secret key or browser cookie. The older Principal-only reader continues exposing no sealed grant.

False/throw/unknown from the selected create method follows the existing callback failure path: orphan grant queue and session revoke, no usable session cookie and no repeated create/new key. The new reader itself returns null for unavailable DATA and never writes, treats it as absence, or authorizes fallback. Existing cleanup awaits may themselves throw and replace an earlier failure; this extension does not claim guaranteed preservation of the original error identity.

Root owns any eventual wrapper of the existing createSession method. After the actual Root origin/native-backing/current prerequisites, that wrapper can bind the same original RP receiver and record, then use its existing captured contribution for one Principal3+session/class2 batch in place of the ordinary create write. It must not first commit Principal3, run ordinary create and then add a class write, or accept a supplied session DTO as original. The Root consumer source v2 currently refuses fresh Principal resolution; until Root implements its genuine prepare, this write hook is unreachable in that branch. This API cannot replace Root's native backing/original request checks before and after awaits. Genuine issuer/registration/controller incarnation, target103, distinct human, qualified policyClock/current admission, actual mount and Financial CAS remain their owners' work.
