# Synthetic 0094 D1 import rehearsal

`takoserver-d1-money-cutover-rehearsal` exercises the audited 0092–0094 SQL on **one new, isolated rehearsal D1**. It creates no database, reads no integration or production target descriptor, and grants no billing cutover permission. The fixture is generated by this source: one synthetic principal and organization, one non-purchased credit lot and matching funding ledger row at 900719925473 cents, with a fixed cursor. No staging export or customer data enters this lane.

Use the normal `takoserver-rehearsal-d1-create` surface first. Preserve its reviewed 0600 input declaration and complete JSON apply result as an owned 0600 receipt, then independently compute SHA-256 digests of their exact bytes. The create result must be terminal for a fresh `takoserver-r-<32-lowercase-hex>` name, with the returned UUID and zero application schema objects. The new surface checks those two files, the exact name/UUID/account tuple, and native D1 get/list before reading or importing its selected database. It requires an explicit rehearsal-scoped `CLOUDFLARE_API_TOKEN`; it cannot use OAuth.

For **each** phase, prepare a new owned 0600 JSON declaration outside the repository, selected by `TAKOSERVER_D1_MONEY_REHEARSAL_DECLARATION_PATH`. Use a fresh protected review file path for that phase. The custody directory must be owned 0700, outside this repository, and retained through the entire sequence:

```json
{
  "kind": "takoserver.money-unit-rehearsal@v1",
  "environment": "rehearsal",
  "accountId": "<32 lowercase hex>",
  "databaseName": "takoserver-r-<32 lowercase hex>",
  "databaseId": "<native UUID>",
  "createDeclarationPath": "/absolute/protected/create.json",
  "createDeclarationDigest": "sha256:<64 lowercase hex>",
  "createReceiptPath": "/absolute/protected/create-result.json",
  "createReceiptDigest": "sha256:<64 lowercase hex>",
  "reviewPath": "/absolute/protected/phase-review.json",
  "custodyDirectory": "/absolute/protected/money-custody",
  "phase": "seed"
}
```

The fixed sequence is `seed`, `freeze`, `prepare`, `classify`, `failure-probe`, `convert`. For each phase, run status with the same reviewed clean commit that will be used for apply:

```bash
bun run deploy -- takoserver-d1-money-cutover-rehearsal --status --environment=rehearsal --commit=<reviewed-clean-40-hex-SHA>
```

Status returns `reviewBinding` and `reviewBindingDigest` without a D1 write. An independent reviewer must inspect the exact account/D1/create custody, audited source prefix, seed and classification fixture, predecessor shape and typed application-row digest, import digest, pinned Wrangler version/launcher/dist-module digests, exact account/D1 import endpoint, each phase's transport, and expected after-state. The reviewer retains the actual analysis as an owned 0600 evidence file outside the repository and writes a protected 0600 record at `reviewPath`:

```json
{
  "kind": "takoserver.money-rehearsal-independent-review@v1",
  "bindingDigest": "sha256:<exact status reviewBindingDigest>",
  "evidencePath": "/absolute/protected/review-evidence.json",
  "evidenceDigest": "sha256:<exact bytes of independent review evidence file>",
  "reviewer": "<independent reviewer identity>"
}
```

Only after that review, run the matching apply command. Apply qualifies the clean remote-reachable commit, checks exact native identity and predecessor again, and creates one no-overwrite dispatch record with protected sealed SQL. Normal phases, including successful `convert`, invoke pinned Wrangler `d1 execute --remote --file`. The `failure-probe` uses a dedicated authenticated TLS observer of Wrangler 4.123.0's same D1 `/import` init, signed R2 upload, ingest and poll protocol, sending the exact sealed SQL bytes and requiring a structured provider `status:error` with the exact missing-table SQL fault. This is separately named in the review binding; a CLI stderr fragment is never accepted as proof. The code verifies native schema/lineage, typed bytes of every application table, financial preimage and aggregates, and foreign keys before writing a terminal record. The probe SQL is the exact sealed 0094 conversion and replacement fences **followed by** the missing-table statement; `convert` uses the unmodified sealed 0094 SQL and must finish at 0094-fenced. The observer qualifies the backend import/rollback behavior, while the successful Wrangler run qualifies its own transport; it does not claim a Wrangler CLI failure observation.

The observer checks the [D1 import API](https://developers.cloudflare.com/api/resources/d1/) envelope and follows the [documented init/upload/ingest/poll sequence](https://developers.cloudflare.com/d1/tutorials/import-to-d1-with-rest-api/). The pinned Wrangler 4.123.0 `executeRemotely` file path computes MD5 from the file and uploads its original bytes; SQL line-ending normalization is confined to its `--command` path. The observer uploads the same sealed UTF-8 bytes only to an HTTPS Cloudflare R2 presigned URL returned by the authenticated, exact-account/UUID D1 init response. A selected-account R2 host or a validated Cloudflare R2 system-account host with an optional bucket label is accepted; arbitrary hosts and redirects are rejected. The terminal receipt records only the host class and SHA-256 of the presigned URI, never the URI or API token. The observer verifies the MD5 ETag and only polls an `active` import until an exact `error` result; unexpected response shapes or acknowledgements leave dispatch custody without a terminal receipt. Review evidence is an owned file whose exact SHA-256 is checked; the reviewer identity and source receipt are operational attestations, not cryptographic signatures.

```bash
bun run deploy -- takoserver-d1-money-cutover-rehearsal --apply --environment=rehearsal --commit=<reviewed-clean-40-hex-SHA>
```

If an import acknowledgement is unknown, the diagnostic marker is absent, or readback is partial/divergent, **do not retry apply**. Status reads the retained dispatch and current native state without sending another import; a dispatched phase remains quarantined. There is no D1 reset/delete, old-cents rollback or automatic target adoption. Record the native failure-probe and successful-conversion terminal receipts as rehearsal evidence for a separate independent review of the actual integration 0094 cutover. Local SQLite tests and source code alone do not prove native D1 `/import` atomicity.
